## Problem Analysis

Using flake.nix has its own biome package version installed (pkgs.biome from nixpkgs).
Using package.json might also have its own biome version installed (node_modules/.bin/biome).
This creates version conflicts and compatibility issues.

Biome usage contexts:
- IDE (nixvim config) as an LSP - currently hardcoded to pkgs.biome
- Via package manager (bunx biome / npx biome) - BROKEN on NixOS due to dynamic linking

Current State:
- applications.nix: biome commented out (no system-wide package)
- lsp.nix: biome LSP uses `package = pkgs.biome` (hardcoded nixpkgs version)
- none-ls.nix: biome formatting enabled (uses nixpkgs version)

**Critical Issue:** Running `bunx biome` fails with:
```
Could not start dynamically linked executable: node_modules/@biomejs/cli-linux-x64/biome
NixOS cannot run dynamically linked executables intended for generic linux environments
```

This is because npm/bun packages download pre-compiled Linux binaries that expect
standard FHS paths (/lib/ld-linux.so), which don't exist on NixOS.

## Proposed Solution: Use Nix-Managed Biome with direnv

### Core Strategy
Since node_modules biome binaries don't work on NixOS, we must use nix-managed biome.
Use direnv + shell.nix to provide project-specific biome versions via nixpkgs.

### Why This Works on NixOS
- Nix packages are patched to work with NixOS's unique filesystem layout
- Avoids dynamic linking issues entirely
- Can still pin specific versions via nixpkgs commit/version
- Works consistently across IDE, CLI, and scripts

### Implementation Plan

#### 1. System-Level Changes (NixOS Configuration)

**A. Enable direnv in home-manager** (add to home-manager/home.nix or create programs/direnv.nix):
```nix
{ ... }:
{
  programs.direnv = {
    enable = true;
    enableZshIntegration = true;
    nix-direnv.enable = true;  # Caches nix-shell for better performance
  };
}
```

**B. Modify nixvim LSP to use PATH** (home-manager/programs/nixvim/plugins/lsp.nix):
```nix
biome = {
  enable = true;
  # Remove these lines:
  # package = pkgs.biome;
  # cmd = [ "${pkgs.biome}/bin/biome" "lsp-proxy" ];

  # LSP will auto-discover biome from PATH (direnv-managed)
};
```

**C. Keep system fallback** (applications.nix line 88):
```nix
biome  # Uncomment - provides fallback when not in a project
```

#### 2. Per-Project Configuration

Create these files in project roots that need biome:

**`.envrc`**:
```bash
use nix
```

**`shell.nix`**:
```nix
{ pkgs ? import <nixpkgs> {} }:

pkgs.mkShell {
  buildInputs = with pkgs; [
    nodejs_22  # or your preferred version
    bun
    biome      # nix-managed biome (works on NixOS)
  ];

  shellHook = ''
    echo "Dev environment loaded"
    echo "Biome: $(which biome) ($(biome --version))"

    # Note: node_modules biome won't work on NixOS
    # We're using nix-provided biome instead
  '';
}
```

**For version pinning**, use a specific nixpkgs commit:
```nix
{ pkgs ? import (fetchTarball {
    url = "https://github.com/NixOS/nixpkgs/archive/COMMIT_HASH.tar.gz";
  }) {}
}:

pkgs.mkShell {
  buildInputs = [ pkgs.biome ];
}
```

#### 3. Alternative: Flake-based (Recommended for version control)

**`flake.nix`**:
```nix
{
  inputs = {
    nixpkgs.url = "github:nixos/nixpkgs/nixos-unstable";
    # Or pin to specific commit for version control:
    # nixpkgs.url = "github:nixos/nixpkgs/COMMIT_HASH";
  };

  outputs = { nixpkgs, ... }:
    let
      system = "x86_64-linux";
      pkgs = nixpkgs.legacyPackages.${system};
    in {
      devShells.${system}.default = pkgs.mkShell {
        buildInputs = with pkgs; [
          nodejs_22
          bun
          biome
        ];

        shellHook = ''
          echo "Biome: $(biome --version)"
        '';
      };
    };
}
```

**`flake.lock`** (generated by `nix flake lock`):
- Pins exact nixpkgs commit
- Ensures reproducible biome version

**`.envrc`**:
```bash
use flake
```

#### 4. Removing biome from package.json

Since biome from node_modules doesn't work on NixOS, remove it from package.json:

```json
{
  "devDependencies": {
    "@biomejs/biome": "..." // Remove this
  }
}
```

Update package.json scripts to use nix-provided biome:
```json
{
  "scripts": {
    "format": "biome format --write .",
    "lint": "biome check ."
  }
}
```

These scripts will use the biome from direnv environment.

### Workflow

**When entering a project directory:**
1. direnv detects `.envrc` and loads nix shell
2. `biome` is added to PATH from nix
3. nixvim LSP finds biome from PATH
4. Package.json scripts use the same nix-provided biome
5. All contexts use identical biome version ✅

**Version control:**
- Flake-based: `flake.lock` pins exact nixpkgs commit → deterministic biome version
- shell.nix-based: Can pin nixpkgs commit in fetchTarball
- System fallback: Uses whatever nixpkgs provides

**Version priority:**
1. Project's direnv environment (from shell.nix/flake.nix)
2. System-wide pkgs.biome (fallback for non-project directories)

### Benefits

✅ **Works on NixOS** - no dynamic linking issues
✅ Consistent version across IDE, CLI, and scripts
✅ Automatic environment switching per project
✅ Version pinning via nix flakes or nixpkgs commits
✅ Fast with nix-direnv caching
✅ IDE integration works seamlessly
✅ No npm/bun dependency for tooling

### Migration Steps

1. **System configuration:**
   ```bash
   # Edit configuration files to:
   # - Enable direnv in home-manager
   # - Modify nixvim biome LSP to use PATH
   # - Uncomment biome in applications.nix

   sudo nixos-rebuild test --flake .#nixos
   ```

2. **Per project:**
   ```bash
   cd ~/my-project

   # Remove biome from package.json
   # Edit package.json to remove @biomejs/biome

   # Create .envrc
   echo "use flake" > .envrc

   # Create flake.nix (use template above)

   # Generate flake.lock
   nix flake lock

   # Allow direnv
   direnv allow

   # Verify
   which biome  # Should show nix store path
   biome --version
   ```

3. **Verify IDE integration:**
   ```bash
   cd ~/my-project
   nvim some-file.js
   # Run in nvim: :LspInfo
   # Should show biome LSP connected
   ```

### Finding Specific Biome Versions

To use a specific biome version, find the nixpkgs commit that has it:

1. Check https://search.nixos.org/packages?query=biome
2. Click on version → "Source" → note the commit hash
3. Use that commit in flake.nix or shell.nix

Example for biome 1.9.4:
```nix
inputs.nixpkgs.url = "github:nixos/nixpkgs/COMMIT_FROM_SEARCH";
```

### Verification Commands

```bash
# In project directory
cd ~/my-project
which biome        # Should show: /nix/store/.../bin/biome
biome --version    # Should match desired version

# In non-project directory
cd ~
which biome        # Should show system fallback or not found

# Check LSP in nvim
nvim test.js
# :LspInfo should show biome connected
```

### Notes

- **Don't use npm/bun/pnpm to install biome** - it won't work on NixOS
- **Use nix for all development tools** on NixOS (biome, prettier, eslint, etc.)
- If you need a version not in nixpkgs, contribute or overlay it
- direnv + nix-direnv is essential for good DX with this approach
